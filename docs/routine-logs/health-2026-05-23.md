## Failure
IG mirror threw at 14:15:38 UTC during the first status-code poll on the freshly-created container:

```
IG status check → 400: {"error":{"message":"Authorization Error","code":100,
"type":"GraphMethodException","error_subcode":33,
"fbtrace_id":"AYWk7xJXIwqmVLy2W1MA_qs"}}
```

Meta error code `100` / subcode `33` = "object does not exist, may have been deleted, or you don't have permission to view it." On a freshly-returned creation_id this is the documented "container not yet registered server-side" transient — not a token problem. The page-access-token + IG-business-account resolution succeeded (the container call before this one returned a creation_id), and FB on the same token chain published cleanly 15 minutes earlier.

## Root cause
`publishToIg` in `app/api/social/ig-mirror/route.ts` throws on the *first* non-ok status response inside its polling loop:

```ts
if (!sRes.ok) throw new Error(`IG status check → ${sRes.status}: ${sText.slice(0, 200)}`);
```

So a one-off blip on attempt 0 (1.5s after container creation) bypasses every subsequent retry and terminates the whole publish. Twelve days running, Meta has been registering the container in <1.5s; today it didn't.

## Fix
PR: https://github.com/neverpeakev/momfluence/pull/87 (branch `claude/fix-content-cron-2026-05-23`)
- Tolerate transient HTTP errors inside the status-poll loop; only surface the most recent error if every attempt fails.
- Widen poll window to 10×2s (20s) from 8×1.5s (12s).
- ERROR / EXPIRED `status_code` values still terminate immediately (real container failure, not transient).
