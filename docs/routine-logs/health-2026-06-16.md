## Root cause (proximate)
`app/api/social/ig-mirror/route.ts` has three silent-failure exit paths
that return 200 with `ok:false` in the response body, but never call
`console.error` and never update the candidate rows. So Vercel logs show
GET `/api/social/ig-mirror` → 200 every day, and the DB shows no error
either. The failure is invisible to every monitoring surface:

1. `META_MARKETING_API_TOKEN` / `META_FB_PAGE_ID` missing — no log.
2. `listPendingIgMirror()` returns empty — no log.
3. `fetchPageContext()` throws (e.g. token expired, IG link broken,
   missing `instagram_basic` / `instagram_content_publish` scope on the
   page token) — no log, no DB tombstone.

Because the FB cron uses the same `META_MARKETING_API_TOKEN` and the same
`/me/accounts` call and succeeds today, the underlying token IS valid for
FB page access. The most likely failure is the second leg of
`fetchPageContext` — the `${pageId}?fields=instagram_business_account`
lookup — either returning no `instagram_business_account` field (link
broken) or 400/403 on missing IG scopes.

Without logs we cannot confirm which. This PR adds the missing logs so
the next run reveals the real reason.

## Fix
Branch `claude/fix-content-cron-2026-06-16` — adds `console.error` /
`console.log` to every silent-failure exit path in `ig-mirror/route.ts`,
and a `console.error` on per-row publish failures. Once merged + deployed,
the next 14:15 UTC cron run will leave a diagnosable trace in Vercel
runtime logs.
