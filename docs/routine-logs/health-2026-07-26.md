## Root cause
`app/api/social/ig-mirror/route.ts` had two pre-flight failure paths that
returned 200 without touching the pending rows:

1. `META_MARKETING_API_TOKEN` / `META_FB_PAGE_ID` missing → return with
   `message` field, but no `markFailed` call.
2. `fetchPageContext` throws (missing IG scope, IG business account unlinked,
   token expired, etc.) → same silent 200.

Because neither path called `markFailed`, the pending rows kept satisfying
`listPendingIgMirror`'s filter forever, and no observable trace of the failure
existed. `fb-daily-generate` successfully uses the same
`META_MARKETING_API_TOKEN` daily, so env vars are set — the failure is
almost certainly in `fetchPageContext`, specifically the
`/{pageId}?fields=instagram_business_account` lookup (needs `instagram_basic`
scope on the user token, and the IG Business Account 17841442248205840 must
still be linked to FB Page 1086292991223812).

## Fix
PR: `claude/fix-content-cron-2026-07-26` (link added below on push).

`app/api/social/ig-mirror/route.ts` — collapse both pre-flight failure paths
into a `bailOut(reason)` helper that:
- calls `markFailed(row.id, 'ig', 'pre-flight: <reason>')` for every pending
  row before responding, so future silent failures become visible in the DB
  and in the next-day health check;
- `console.error`s the reason so the Vercel `error/serverless` log stream
  picks it up.

This does **not** fix the underlying META permission/link issue. After merge
+ deploy, the next 14:15 UTC run will emit a concrete error (in DB
`error_message` and Vercel logs) which the operator can then act on — likely
reconnecting the IG Business Account on the FB Page or refreshing the system
user token with `instagram_basic` + `instagram_content_publish`.
