## Why nobody noticed
- `/api/social/ig-mirror` returned HTTP 200 on every daily cron tick (verified today: 14:15:08 → 200).
- No serverless error logs, no entry in Vercel `get_runtime_errors`.
- No `error_message` written to any of the 30 stuck rows.
- Root cause: when `fetchPageContext` throws inside the route, the catch branch returned `{ok: false, message: "auth/page-context: ..."}` with **status 200** and **did not touch the pending rows**. Every subsequent cron then re-selected the same rows and silently returned "auth/page-context" again. This is a code observability bug (fixed in the PR below).

## Likely root cause of the mirror failure itself
- `fb-daily-generate` continues to publish successfully, so `META_MARKETING_API_TOKEN` and `/me/accounts` → page token path both still work.
- `ig-mirror` does the same page token exchange but then additionally requests `?fields=instagram_business_account` on the FB Page. If that field is missing, it throws `No Instagram Business Account linked to FB Page 1086292991223812`.
- Most probable operational fix: **re-link the IG Business Account (17841442248205840) to FB Page momfluence in Meta Business Manager, then re-grant `instagram_basic` + `instagram_content_publish` scopes on the system-user token**. This is not something the cron can self-heal.
- After the PR below deploys, tomorrow's tick will write the real Graph API error message into every stuck row's `error_message` column — that will confirm the exact failure mode (permission scope vs. link severed vs. token expiry).
