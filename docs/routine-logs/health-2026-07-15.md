## Root cause (diagnosed; not fully confirmed without new logs)
`app/api/social/ig-mirror/route.ts` has three early-return paths that respond `200` with a `message` field but emit **no** `console.log` / `console.error`:
1. missing env vars,
2. `pending.length === 0`,
3. `fetchPageContext` failure.

Vercel's runtime log records the HTTP line but not the response body, so any of these paths is invisible after the fact. The most likely culprit — since FB works, so the user token is fine — is `fetchPageContext` failing on the second call:

```
GET /{pageId}?fields=instagram_business_account
```

If the `instagram_basic` permission on the derived Page access token has lapsed, this returns without `instagram_business_account`, and line 76 throws `No Instagram Business Account linked to FB Page ...`. That gets swallowed into a silent 200 with `message: "auth/page-context: ..."`. This fits everything we see: (a) FB works, (b) the IG endpoint 200s immediately, (c) no pre-warm render fetch follows in the logs, (d) all 41 pending rows stay in `fb_published` (no `markFailed` calls).
