## Diagnosis
Vercel runtime logs show `/api/social/ig-mirror` returning **200** at 14:15:08 UTC each day with no errors logged. No `render/post/<slug>.png` hits occur in the 14:14–14:18 window — meaning execution never reached the per-row warm-fetch loop. Eliminating return paths:
- 401 (`authorized() == false`) — would have shown as 401, not 200.
- 200 "env vars missing" — same `META_MARKETING_API_TOKEN` / `META_FB_PAGE_ID` env vars are used by `fb-daily-generate`, which is succeeding daily.
- 200 "nothing to mirror" — `listPendingIgMirror` filter (`fb_published_at IS NOT NULL AND ig_published_at IS NULL AND status='fb_published'`) matches 10 backlog rows when run directly via Supabase MCP; cannot be empty.
- 200 "auth/page-context: …" — **only remaining path.** `fetchPageContext` step 1 (`/me/accounts`) shares code with `fb-daily-generate` and that flow is healthy, so the throw is almost certainly at step 2: `GET /{pageId}?fields=instagram_business_account` returning no `instagram_business_account` field → `throw new Error("No Instagram Business Account linked to FB Page 1086292991223812")`.

Most likely root cause is **operational, not code**: the user/admin token lost `instagram_basic` (and/or `instagram_content_publish`) scope, or the IG Business Account was unlinked from the FB Page around 2026-05-27. FB posting continues because that uses `pages_manage_posts` only.

## Code fix (PR)
The cron *should* have surfaced this on day 1. The current `try/catch` around `fetchPageContext` returns a 200 with the error in the JSON body but leaves every pending row untouched — invisible to the morning audit because `error_message` stays null. PR turns this into a hard, visible failure: each pending row gets `markFailed(..., 'ig', 'auth/page-context: …')` so the next audit sees `status='ig_failed'` with the actual Meta error message in `error_message`.

PR: https://github.com/neverpeakev/momfluence/pull/118 (branch `claude/fix-content-cron-2026-06-10`)
