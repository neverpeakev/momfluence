## Diagnosis
The IG mirror endpoint (`app/api/social/ig-mirror/route.ts`) has three early-return paths that all return HTTP 200 without touching the row:
1. Missing env vars → `{message: "META_MARKETING_API_TOKEN or META_FB_PAGE_ID not set"}` — unlikely, FB endpoint used the same vars successfully.
2. `fetchPageContext` throws → `{message: "auth/page-context: <err>"}` — plausible, this is the only IG-specific call (the linked-IG lookup).
3. Empty pending list → `{message: "nothing to mirror"}` — should not have applied; the row was fb_published well before 14:15.

The 200 response in ~8s is too fast for a full mirror (needs ≥15s for the 8×1.5s status polling loop), and too slow for the "nothing to mirror" fast-exit. It matches the fetchPageContext-throws scenario: `/me/accounts` (~2s) + `/{pageId}?fields=instagram_business_account` (~2s) + overhead → 8s total.

Root cause candidates (ranked):
- **A. IG link scope regressed**: the page access token no longer includes `instagram_business_management` / `instagram_content_publish`, so `instagram_business_account` returns absent or errors → `fetchPageContext` throws "No Instagram Business Account linked".
- **B. Meta Graph API v20 deprecation**: v20.0 was sunsetted; API returns a versioning error. Would also break FB, so lower probability given today's FB success.
- **C. Transient Meta API 5xx during that one 8-second window**: possible but nothing in Vercel error logs suggests it.

Cannot confirm which without the endpoint logging the actual failure — every early-return currently produces a 200 with the reason ONLY in the JSON response body, which Vercel runtime logs do not capture.

## Fix (this PR)
`app/api/social/ig-mirror/route.ts` — add `console.error` at every early-return path so Vercel runtime logs surface the failure reason. No behavior change; pure observability. Next daily run (or the manual retry below) will tell us which of A/B/C is happening.
