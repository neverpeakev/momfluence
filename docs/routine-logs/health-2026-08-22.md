## Root cause
`app/api/social/ig-mirror/route.ts` L177-192: when `fetchPageContext` (page-token + linked-IG-business-account lookup on the Meta Graph API) throws, the endpoint returns `200 OK` with the error only in the response body — no `console.error`, no row updates. The daily health check can't distinguish this from a healthy pending state, and Vercel logs show only the middleware line (no serverless output), so there is zero visibility into failures.

Vercel logs for today confirm this — a bare `GET /api/social/ig-mirror 200` at 14:15:57 with no serverless output and no invocations of `/api/render/post/...png` from the mirror.

The Meta-side failure itself is almost certainly the IG business account being unlinked from FB Page `1086292991223812` (or the marketing token missing `instagram_basic`/`pages_show_list` scope) — the same failure mode the May–July backlog note describes.

## Fix (this PR)
Branch: `claude/fix-content-cron-2026-08-22`
`app/api/social/ig-mirror/route.ts`:
1. When `fetchPageContext` throws AFTER `listPendingIgMirror` returns at least one row, mark every pending row `ig_failed` with the `auth/page-context: ...` message. Same "poison-pill" idempotency the per-row publish path already uses — makes the failure durable and visible to `health-*.md` checks.
2. Add `console.log`/`console.error` at every outcome (nothing-to-mirror, page-context failure, batch done) so Vercel serverless logs actually show what the endpoint did.

This does NOT restore IG publishing — that requires:
1. Re-link `1086292991223812`'s Instagram Business Account in Meta Business Suite → Business Settings → Accounts → Instagram accounts.
2. Verify `META_MARKETING_API_TOKEN` still has `instagram_basic`, `instagram_content_publish`, and `pages_show_list` scopes.
3. Manually reset today's row (and the 25 stale ones, if reposting is desired) by clearing `status`/`errored_at`/`error_message` back to `fb_published` state, or leave them ig_failed and accept the loss.
