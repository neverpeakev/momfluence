## Root cause (partial)
`app/api/social/ig-mirror/route.ts` has two early-return paths that exit with HTTP 200 without flagging any pending row as failed:
1. Missing `META_MARKETING_API_TOKEN` or `META_FB_PAGE_ID` env (line 153–162 of the pre-fix code).
2. `fetchPageContext` throws — e.g. expired user token, transient Graph API 5xx, network blip (line 178–192).

Either path silently leaves the row at `status='fb_published'` with no error trail. That is what today's row shows, so one of those two paths fired.

Discriminating which one needs Vercel runtime logs. Vercel MCP is **not available in this session** (only Supabase + GitHub MCPs were exposed), and `vercel` CLI is not installed in the sandbox. I cannot reach `momfluence.app` directly either (egress policy blocks the host). Operator follow-up needed to read the 14:15 UTC log line for `/api/social/ig-mirror`.

Note: FB cron at 14:00 UTC succeeded using the same `authorized()` function and the same `META_*` env vars, so the most likely culprit is `fetchPageContext` (Graph API hiccup at 14:15 UTC) rather than missing env or a 401.

## Fix shipped
PR: branch `claude/fix-content-cron-2026-06-30` (PR link below once opened).

`app/api/social/ig-mirror/route.ts` — both setup-failure paths now call `markFailed(row.id, "ig", reason)` for every row returned by `listPendingIgMirror`, so the failure surfaces on the row itself (with the underlying Graph-API error message) instead of silently disappearing. Matches the design intent already documented in the file header ("Failed rows are marked ig_failed with the error message").

The fix is observability-only — it does not change FB → IG behavior when things succeed, and it does not auto-retry. Failed rows still need a manual reset to `status='fb_published'` before they get re-attempted (same as before).
