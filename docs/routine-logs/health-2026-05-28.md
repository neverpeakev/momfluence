# Daily content cron health — 2026-05-28

Status: **FAILED — no post for today (state c); fix PR opened**

No `generated_posts` row exists for 2026-05-28. The FB generator cron fired on
schedule but threw during post generation, before any row was inserted, so
nothing was published to Facebook or Instagram today.

## What happened
- `0 14 * * *` cron fired: `GET /api/social/fb-daily-generate` at 14:00:38 UTC → **HTTP 200**.
- `15 14 * * *` cron fired: `GET /api/social/ig-mirror` at 14:15:04 UTC → HTTP 200 (no-op; nothing to mirror).
- `SELECT ... FROM generated_posts WHERE created_at >= date_trunc('day', now())` → **0 rows**.

## Root cause
The generator threw at `stage=generate` (inside `generateDailyPost`) **before**
reaching `insertPending`. Confirmed from Vercel runtime logs by string-matching
the collapsed log bundle for the 14:00:38 request:
- `query="generateDailyPost"` → matches (this literal only appears in the throw at `lib/social/post-generator.ts:417`, `generateDailyPost failed after N attempts`).
- `query="markFbPublished"` → no match (that stage was never reached).

So all `maxAttempts` (3) generation attempts failed and the function threw. Two
defects combine to make this a silent, recurring outage:

1. **Silent failure.** `app/api/social/fb-daily-generate/route.ts` returns HTTP
   200 even when generation fails before `insertPending`. With no row created,
   the failure is recorded nowhere — `generated_posts` (the system of record) is
   empty for the day and the Vercel cron run reports green. This is why the same
   "no row" outage already happened on **2026-05-25** and went unnoticed until
   this supervision run.
2. **Generation too fragile.** `MAX_TOKENS = 1500` leaves little headroom for a
   300-word caption + rationale + JSON scaffolding; a verbose generation gets
   truncated mid-JSON, fails `JSON.parse`, and when it happens on every attempt
   the whole day is lost. The exact last-error string for today is not
   retrievable — the runtime-logs tool collapses the message, and 2026-05-25
   logs are past the billing/retention window (`ExceedsBillingLimitError`). The
   angle-dedup pool is *not* the cause: only 15 rows exist and every angle_tag
   is distinct.

This is unrelated to the 2026-05-26 IG-mirror fix (PR #95); 2026-05-27 published
end-to-end cleanly.

## Fix
PR: https://github.com/neverpeakev/momfluence/pull/97 (branch `claude/fix-content-cron-2026-05-28`)
1. `app/api/social/fb-daily-generate/route.ts` — return **500** when the failure
   happens before a row exists (failed run becomes visible in Vercel's cron
   dashboard/alerting). Keep 200 once a row exists, since the row already records
   the failure and a non-200 could trigger a retry that double-publishes.
2. `lib/social/post-generator.ts` — `MAX_TOKENS` 1500 → 2400 (prevents JSON
   truncation on verbose days) and default `maxAttempts` 3 → 5 (more resilience).
