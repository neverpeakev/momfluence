## Root-cause hypothesis
The IG-mirror endpoint (`app/api/social/ig-mirror/route.ts`) has three pre-per-row-loop exits that return 200 with `ok:false` and NO write to the row:
1. `authorized(req)` → 401 (rules out — same `CRON_SECRET` bearer as `/fb-daily-generate`, which succeeds daily).
2. Missing `META_MARKETING_API_TOKEN` / `META_FB_PAGE_ID` (rules out — FB endpoint uses the same env vars and works).
3. **`fetchPageContext` throws** — `/me/accounts` finds the page (same as FB path) but the follow-up `/{pageId}?fields=instagram_business_account` returns without the field → `throw "No Instagram Business Account linked to FB Page 1086292991223812"`.

Path 3 is the most likely culprit. The Marketing-API-scoped user token (`META_MARKETING_API_TOKEN`) may be missing the **`instagram_basic`** (and probably `instagram_content_publish`) scopes — the FB Graph API silently omits `instagram_business_account` when the caller lacks `instagram_basic`. FB posting via `/{pageId}/photos` requires `pages_manage_posts` only, which is why FB continues to work while IG has been broken for two months.

I cannot verify the token scopes from this session (no Vercel MCP; the endpoint is behind Vercel Deployment Protection so an unauthenticated GET returns 403; I don't have `CRON_SECRET`).
