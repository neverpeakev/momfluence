## Diagnosis
Working through the handler's exit paths against the observed outcome (returned 200, DB unchanged, no error_message, no `console.error` in logs):
- `pending.length === 0` — ruled out; today's row matches `listPendingIgMirror`.
- `!userToken || !pageId` — ruled out; the same env vars just worked at 14:02 in `/api/social/fb-daily-generate`.
- `fetchPageContext` threw and was caught — **most likely.** The catch on line 182 of `app/api/social/ig-mirror/route.ts` returns `NextResponse.json({ message: "auth/page-context: ..." })` with **no `console.error`**, so a failure here leaves *no* trace in Vercel runtime logs (cron ignores response bodies). This exit path is the only one consistent with all four observations. Most probable underlying cause: the system-user token is missing `instagram_basic` / `instagram_content_publish` for the linked IG business account, or the `instagram_business_account` field lookup transiently returned no id.
- `publishToIg` failure would have flipped the row to `ig_failed` with `error_message` set. Ruled out.

## Fix pushed
PR: **claude/fix-content-cron-2026-08-03** (link filled in below after PR create).

Minimal change to `app/api/social/ig-mirror/route.ts`:
1. `console.error` before returning `auth/page-context: <msg>` so the next occurrence is diagnosable from the log alone.
2. `console.error` when env vars are unset.
3. `console.log` on entry with pending count + slugs so we always know the run executed and what it saw.

This does **not** address the underlying Meta-side cause (unknowable without the console.error we just added, or a manual invocation with `CRON_SECRET`).
