## Root cause
Two layers.

**Proximate (Meta config — needs human verification).** ig-mirror returned
200 with the row untouched. Walking `app/api/social/ig-mirror/route.ts`:
- The row matches `listPendingIgMirror` (`fb_published_at` set,
  `ig_published_at` null, `status='fb_published'`), so the "nothing to
  mirror" early-exit is ruled out.
- The FB cron's success at 14:01 proves the shared env vars
  (`META_MARKETING_API_TOKEN`, `META_FB_PAGE_ID`) and the
  `/me/accounts` page-token resolution were valid at 14:15 — ruling out the
  env-missing branch and the page-token lookup.
- The only path left that yields *200 + row untouched + nothing logged* is
  `fetchPageContext` throwing at the one step the FB route does not perform:
  `GET /{pageId}?fields=instagram_business_account` (route.ts L69-76).

  The FB page token can post photos (`pages_manage_posts`) yet still return
  an empty `instagram_business_account` if it lacks `instagram_basic` /
  `instagram_content_publish` scope, or if the IG Business Account link was
  dropped. That produces `"No Instagram Business Account linked to FB Page
  1086292991223812"` (or a Graph permission error) → the catch at L182-192.
  I could not confirm the exact Graph error directly because
  `META_MARKETING_API_TOKEN` / `CRON_SECRET` are Vercel secrets not exposed
  to this session.

**Code/observability bug (fixed in this PR).** That catch — and the
env-missing branch — returned 200 **without `console.error` and without
marking the pending rows `ig_failed`**. The per-row failure path inside the
loop marks rows + pushes the error, but the batch-level precondition
failures were silent, so the failure was invisible to BOTH the runtime logs
(empty message) and the status/`error_message` monitor. This asymmetry is
the defect.

## Fix
PR: https://github.com/neverpeakev/momfluence/pull/PENDING (branch `claude/fix-content-cron-2026-05-29`)
- `app/api/social/ig-mirror/route.ts` — add `console.error` to the
  env-missing branch and the auth/page-context catch (parity with the FB
  route's stage-level logging). Rows are intentionally **left as
  `fb_published`, not marked `ig_failed`**, so a future run auto-retries the
  mirror once the token/IG-link is corrected — `ig_failed` is terminal and
  excluded from future runs by design, which would burn the post on a
  transient/config blip.
