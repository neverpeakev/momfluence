Today's FB cron working confirms `META_MARKETING_API_TOKEN` and `META_FB_PAGE_ID` ARE present on the current production deployment — so the env-var early-exit isn't the culprit. That narrows the silent failure to either the auth check (Vercel Cron not sending the Bearer header) or `fetchPageContext` throwing on Meta API. The Bearer header has been working for `fb-daily-generate` and `inbox-agent` on the same deployment, so by elimination it's almost certainly `fetchPageContext` — i.e. Meta's `/me/accounts` or `/{pageId}?fields=instagram_business_account` call is failing.
