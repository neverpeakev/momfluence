# Daily content cron health — 2026-07-16

**Status:** FAILED. FB cron fired on schedule but produced no row in `generated_posts`.

## What I found

- `SELECT ... FROM generated_posts WHERE created_at >= date_trunc('day', now())` → 0 rows.
- Vercel runtime log at `14:00:42 UTC` for `/api/social/fb-daily-generate`:

  ```
  [fb-daily-generate] failed at stage=generate: generateDailyPost failed after 3 attempts.
  Last error: not valid JSON (first 200 chars: {
    "angle_tag": "flu-shot-clinic-lollipop-rec",
    "content_format": "anecdote",
    ...
    "display": "She named the lollipops
       in the flu shot line.",
    "body": "Three moms asked. One brand paid.",
  ```

  The `display` value contains a **raw newline** (not `\n`). `JSON.parse` rejects it.
  All 3 retries hit the same failure because the prompt itself is what's causing it.

- IG mirror at 14:15 UTC never had a `fb_published` row to mirror, so IG was a
  silent no-op (unrelated to today's failure; the ongoing IG issue is being
  tracked in PRs #151 / #153 / #159 which are still unmerged).

## Root cause

`lib/social/post-generator.ts` builds `SYSTEM_PROMPT` as a JavaScript template
literal (backticks). In a template literal `\n` is a **real newline character**,
not the two-character sequence `\` + `n`. The prompt contained two lines
telling Claude "can use `\n` for line break", but what Claude actually saw was:

    can use
     for line break

Claude reasonably interpreted that as permission to put a raw newline inside
the JSON `display` value — which is invalid JSON per RFC 8259 §7 ("literal
control characters MUST be escaped inside strings").

## Fix — PR #TBD (branch `claude/fix-content-cron-2026-07-16`)

1. `lib/social/post-generator.ts` — the two `\n` occurrences in the prompt
   are escaped to `\\n` so Claude sees the two-character escape sequence
   literally, and the sentence is rewritten to be explicit that a raw
   newline is invalid.
2. Defensive `escapeRawNewlinesInStrings` helper: after a `JSON.parse`
   failure, walk the response and escape raw `\n`/`\r`/`\t` that appear
   inside a quoted string literal, then retry the parse. Belt-and-suspenders
   so a stray raw newline can't strand the daily cron again.
