## Root cause

**Two issues, one PR for one of them.**

1. **Code bug (this PR fixes):** in `app/api/social/ig-mirror/route.ts` the `fetchPageContext()` failure branch (lines 178–192 pre-fix) returns 200 with the error in the response body but **does not mark any of the pending rows**. Pending rows therefore stay `fb_published` forever, the next run sees the same backlog, and nothing surfaces in `generated_posts.error_message` for monitoring to alert on. This is why 5 days of failures looked indistinguishable from `nothing to mirror` in the DB.

2. **Underlying Meta auth issue (not fixed by code — manual):** `fetchPageContext` is almost certainly throwing on either `/me/accounts` (token expired/missing scope) or `/{pageId}?fields=instagram_business_account` (no IG Business Account visible to this token). The FB cron uses only `/me/accounts` + `/{pageId}/photos` and is succeeding, which narrows it: the user-token's IG-side scopes (`instagram_basic`, `instagram_content_publish`) are likely the broken piece, or the IG Business Account link to the FB Page was reset. **You need to re-authorize `META_MARKETING_API_TOKEN` with IG scopes in Meta Business settings.**

## Why I can't pin the exact Meta error from inside the box

`ig-mirror` returned 200 with no `console.error` and no DB write — Vercel runtime logs show only the bare request line. The route already had the diagnostic info (in the JSON response body) but threw it away. After this PR, the next failed run will write the exact Meta error into every pending row's `error_message`.

## Fix (this PR)

PR: <will-be-filled-after-create> — branch `claude/fix-content-cron-2026-06-04`

`app/api/social/ig-mirror/route.ts`: when `fetchPageContext` throws, iterate the `pending` list and call `markFailed(row.id, "ig", "auth/page-context: <msg>")` for each, plus a `console.error` so it shows up in Vercel runtime logs at level=error. Return the same 200 response so Vercel doesn't retry-storm.

## After the user fixes the Meta token

Once `META_MARKETING_API_TOKEN` is re-issued with IG scopes, the backlog rows will be in `ig_failed` (terminal) — they will NOT auto-retry. To recover them, run:

```sql
UPDATE public.generated_posts
SET status = 'fb_published', errored_at = NULL, error_message = NULL
WHERE status = 'ig_failed'
  AND ig_published_at IS NULL
  AND fb_published_at IS NOT NULL
  AND created_at >= '2026-05-29';
```

The next 14:15 UTC cron will pick them up. IG's 25-publishes-per-24h limit easily covers 5 rows.
