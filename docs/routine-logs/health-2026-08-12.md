## Root cause
`app/api/social/ig-mirror/route.ts` catches `fetchPageContext` errors
(the "no IG Business Account linked to FB Page" case, plus any Meta
Graph auth blip) and returns HTTP 200 with the message in the body,
but does NOT `console.error` and does NOT `markFailed` the pending row.
Result: every daily run silently no-ops, `error_message` stays NULL, the
row stays `fb_published`, and the backlog grows.

Prior `error_message` values on 2026-07-19..27 rows (hand-written by an
earlier Claude routine on 2026-07-29) name the underlying cause:

> "IG business account was unlinked from the FB Page ~2026-05-28, so
> this post was never mirrored. Marked ig_failed on 2026-07-29 by Claude
> to prevent the mirror cron from bulk-publishing stale content once the
> IG link is restored."

Between 2026-07-29 and 2026-08-12 the same accumulation resumed because
the underlying IG link was not restored AND the route still swallowed
the error, so no signal reached this health check.

## Fix (code)
PR: draft — branch `claude/fix-content-cron-2026-08-12`
- `app/api/social/ig-mirror/route.ts` — on `fetchPageContext` failure,
  `console.error` the wrapped message AND `markFailed` every pending row
  with the same message. This makes the failure visible in Vercel logs
  and in `generated_posts.error_message`, and prevents a growing backlog
  from bulk-publishing on relink.

The code fix does NOT restore IG posting — it only makes the failure
loud and idempotent. The underlying account link still needs a human.
