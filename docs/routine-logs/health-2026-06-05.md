## Diagnosis

The IG mirror cron at 14:15 UTC returns 200 in ~8s without updating any row and
without emitting any logs. Because no row was marked `ig_failed`, the loop body
in `app/api/social/ig-mirror/route.ts` never ran — execution stopped at one of
the silent early-return paths:

1. `META_*` env vars missing — unlikely; the FB cron uses the same vars and works.
2. `listPendingIgMirror` returned `[]` — unlikely; the DB clearly has matching rows
   and the same Supabase admin client successfully inserts/updates from FB cron.
3. `fetchPageContext` threw — **most likely**. The IG lookup
   (`/{pageId}?fields=instagram_business_account`) requires `instagram_basic`
   scope on the page access token. If that scope was dropped when the system
   user token was last rotated, the lookup returns 200 with an empty body and
   the route returns `auth/page-context: No Instagram Business Account linked…`
   to the cron — which Vercel sees as a clean 200.

## Fix shipped

PR: claude/fix-content-cron-2026-06-05

Two changes to `app/api/social/ig-mirror/route.ts`:

- **Diagnostic logging.** All silent early-return paths now `console.error`
  (or `console.log` for the idle case) so the next cron tick surfaces the
  actual cause in Vercel runtime logs.
- **`META_IG_BUSINESS_ID` override.** If set, the route skips the
  `instagram_business_account` lookup entirely and uses the env value as the
  IG id. This unsticks the cron immediately even if the token's IG scopes are
  broken. The known IG id for the momfluence FB Page is `17841442248205840` —
  setting that in Vercel env will make tomorrow's run work.
