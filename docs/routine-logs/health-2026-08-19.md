## Diagnosis
`app/api/social/ig-mirror/route.ts` has **zero `console.error` / `console.log`** on any early-return path. Four different code paths return before touching `generated_posts`, and today's request took one of them without leaving a trace:
1. `authorized(req) === false` → 401 (ruled out — response was 200)
2. `META_MARKETING_API_TOKEN` or `META_FB_PAGE_ID` unset → 200 with `message: "META_MARKETING_API_TOKEN or META_FB_PAGE_ID not set"`
3. `listPendingIgMirror()` returns empty → 200 with `message: "nothing to mirror"` (ruled out — 10 pending rows exist)
4. `fetchPageContext()` throws (bad token, IG link removed, page id mismatch) → 200 with `message: "auth/page-context: ${err}"`

Most likely candidate: **(4)** — the Meta long-lived page-access-token has expired, or the Instagram Business Account link on FB Page `1086292991223812` was removed. The FB cron only needs `/me/accounts` + `/{page-id}/feed`; the IG cron additionally needs `instagram_business_account`, which is what would newly fail.

Less likely: (2) — different env scoping between the two cron functions in Vercel.

Cannot distinguish (2) vs (4) without either (a) logs in the route, or (b) a manual `curl` with `Authorization: Bearer $CRON_SECRET`.
