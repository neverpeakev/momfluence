## Root cause
`fetchPageAccessToken` in `app/api/social/fb-daily-generate/route.ts` made a single `GET /me/accounts` call with no retry. FB Graph occasionally returns 5xx with `OAuthException code 1 "An unknown error has occurred"` — Meta's generic transient error. One blip on that single call terminally marks the row `fb_failed` even though the user token, page id, and Claude generation were all fine. Vercel runtime logs confirm the cron fired at 14:00:42 UTC and the route returned 200 (route catches and persists errors), so the only failure was FB's response.

`fetchPageContext` in `app/api/social/ig-mirror/route.ts` had the same retryless pattern on `/me/accounts` and on the IG-account lookup — same latent failure mode.

## Fix
PR: claude/fix-content-cron-2026-06-12 — adds retry-with-backoff (0 / 1.5s / 4s) on 5xx and network errors to both Graph-API token lookups, matching the pattern already used by `fetchRenderedPng` (added in PR #26 on 2026-05-13 for a structurally identical render-fetch issue). 4xx responses still throw immediately so a real token revocation or scope change surfaces as a hard failure, not a hidden retry storm.
