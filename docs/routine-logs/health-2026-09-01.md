## Root cause (code bug — fixed in this PR)
`ig-mirror/route.ts` line 176-192: `fetchPageContext` throw is caught and
converted to `NextResponse.json({ ok:false, message: "auth/page-context: ..." })`
with **no console.error**, so a genuinely broken pipeline looks identical
to a healthy run in Vercel logs. And pending rows are not marked
`ig_failed`, so they silently accumulate in `fb_published`. Contrast with
the per-row publishToIg catch which does call `markFailed` — those failures
are visible.

## Fix in this PR
`app/api/social/ig-mirror/route.ts`:
1. `console.error` at every non-success return (env missing, auth failed,
   page-context failed) so systemic failures surface in Vercel error logs.
2. Also `console.log` the "nothing to mirror" and success counts so the
   endpoint's real state is legible without dumping the response body.

Does **not** auto-mark rows `ig_failed` on `fetchPageContext` failure —
that failure mode is often transient (rate limit, token refresh) and we
don't want a 60-second Meta hiccup to permanently discard the daily post.
Individual-row failures (publishToIg) already mark `ig_failed`, unchanged.
