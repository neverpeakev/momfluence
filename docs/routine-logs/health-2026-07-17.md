## The systemic problem

Ran a lookback: **IG mirror has silently failed every day since 2026-05-29**
(seven weeks). Last successful `ig_published` row was 2026-05-27. The row just
before the silence (2026-05-26) marked itself `ig_failed` with:

    IG status check → 400: {"error":{"message":"Authorization Error",
    "code":100,"type":"GraphMethodException","error_subcode":33, ...}}

Meta subcode 33 = "object doesn't exist / missing permissions / unsupported."
That row failed *inside* the per-row loop, so the error surfaced. Since then,
zero rows carry any error — every failure has been earlier in the flow.

## Root cause of the silence (code bug)

`app/api/social/ig-mirror/route.ts` has three early-exit paths that return
`{ok:false}` with **HTTP 200** and touch no rows:

1. Missing `META_MARKETING_API_TOKEN` / `META_FB_PAGE_ID`
2. `listPendingIgMirror` returns empty
3. `fetchPageContext` throws (bad token, IG account not resolvable,
   `/me/accounts` denied, etc.)

Paths 1 & 3 log nothing to `console.error` and mark no rows. So Vercel logs
show 200 and the DB shows the row still `fb_published` — indistinguishable
from a healthy no-op.

Since the FB path uses the same `META_MARKETING_API_TOKEN` and worked at
14:02, path 1 is ruled out. Since the pending-list filter matches today's
row, path 2 is ruled out. **Path 3 is the culprit** — almost certainly a
Meta token/permission issue: either the User token was rotated with
scopes that permit `/me/accounts` (works for FB posting) but not
`instagram_basic` / `instagram_content_publish` (needed to resolve
`instagram_business_account` on the Page), OR the token has expired for
IG use specifically.

## Fix pushed

PR `claude/fix-content-cron-2026-07-17` adds:

- `console.error` on both early-exit paths (makes them appear in Vercel
  runtime errors)
- `markFailed(row.id, "ig", msg)` on every pending row when
  `fetchPageContext` fails (surfaces the actual Meta error in
  `generated_posts.error_message`)

This is an **observability fix**, not a root-cause fix. The Meta token
still needs a look:

- Verify `META_MARKETING_API_TOKEN` in Vercel env has scopes
  `pages_show_list`, `pages_read_engagement`, `pages_manage_posts`,
  `instagram_basic`, `instagram_content_publish`, `business_management`.
- Or regenerate a fresh long-lived Page/System-User token from Meta
  Business Suite with the IG scopes above.
- Re-run the ig-mirror after the token fix and confirm today's row
  transitions to `ig_published`.

Once the token is fixed, tomorrow's cron will succeed. If it fails again,
the new logging will show the exact Meta error in
`generated_posts.error_message` and in the Vercel runtime errors dashboard.
