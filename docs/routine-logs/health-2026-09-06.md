## What went wrong

Two compounding problems, one upstream (needs user action) and one code bug (fixed by this PR).

### 1. Upstream: IG Business Account unlinked from FB Page (~2026-05-28)

A previous session on 2026-07-29 bulk-annotated the May 29 – Jul 27 backlog
rows with `error_message = "skipped-stale-backlog: IG business account was
unlinked from the FB Page ~2026-05-28..."`. That diagnosis still stands —
no code, cron, or Meta app change has been made since, and today's
run reproduces the exact same behaviour Meta's Graph API returns when an
IG business account is not linked to a FB Page.

**Action required from a human:** re-link the Momfluence IG account
(`17841442248205840`) to the FB Page (`1086292991223812`) via
Meta Business Suite → Settings → Instagram accounts. Until this happens
no future post will mirror to IG; the fix in this PR only stops the
failure from being silent.

### 2. Code bug: ig-mirror global-auth failures were silent

`app/api/social/ig-mirror/route.ts` had three global-early-exit paths
(missing env var, `fetchPageContext` throws, per-row loop bypassed) that
all `return NextResponse.json({ ok: false, ..., message })` with **HTTP
200** and without touching any pending row. Consequences:

- Vercel Cron treated every one of the last 39 daily runs as a healthy
  200, so no alert ever fired.
- Rows were never marked `ig_failed`, so `listPendingIgMirror` kept
  returning the full backlog on every run. If IG is ever re-linked and
  we deploy without pruning first, one cron tick would try to
  bulk-publish 39 posts — well over IG's 25/day rate limit and, more
  importantly, chronologically confusing content.

## Fix (this PR)

Branch: `claude/fix-content-cron-2026-09-06`
File: `app/api/social/ig-mirror/route.ts`

On both global failure paths (missing META env vars, `fetchPageContext`
throws), the route now:
1. Calls `markFailed(row.id, "ig", <reason>)` for every currently pending
   row (via `Promise.allSettled` so one Supabase blip can't hide the
   others).
2. Returns HTTP **500** with the same message, so Vercel Cron surfaces
   the failure to alerting instead of counting it as a healthy tick.

Per-row failures inside the loop already used `markFailed` — that path
was fine and is unchanged.

```sql
  AND ig_published_at IS NULL
  AND fb_published_at < now() - interval '1 day';
```
