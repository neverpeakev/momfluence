## Root cause
`app/api/render/post/[slug]/route.ts` wrapped `getBySlug(slug)` in `.catch(() => null)`, which collapses two distinct failure modes ("row genuinely missing" and "transient Supabase lookup error") into a single 404 response. The row for `gen-2026-05-13-ksr6e` was in fact present in `generated_posts` at the time of the render request (still there now), so the 404 must have come from a swallowed lookup-path error, not a missing record. Vercel runtime logs confirm: 01:20:36 POST `/api/social/fb-daily-generate` → 200, 01:20:47 GET `/api/render/post/gen-2026-05-13-ksr6e...` → 404. A manual POST re-trigger at 01:26:38 then succeeded on its own freshly-generated slug.

## Fix
PR: https://github.com/neverpeakev/momfluence/pull/26 (branch `claude/fix-content-cron-2026-05-13`)
1. `app/api/render/post/[slug]/route.ts` — separate lookup errors (500) from genuine misses (404); log the underlying message.
2. `app/api/social/fb-daily-generate/route.ts` — retry `fetchRenderedPng` with backoff (0 / 1.5s / 4s) so a transient blip no longer terminally marks the row `fb_failed`.
