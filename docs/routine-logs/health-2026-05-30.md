Identical to 2026-05-28 — the silent pre-insert failure PR #97 was opened to fix. `app/api/social/fb-daily-generate/route.ts:206-222` returns HTTP 200 with `{ ok: false, error, stage }` even when the failure happens before `insertPending` (so `row === null` and there's nowhere to record the error). Vercel cron sees green, the system of record (`generated_posts`) has no row, and the failure is invisible to both the runtime-logs query and the status/`error_message` monitor.

Today's specific throw stage isn't directly retrievable — the runtime-logs tool returned only the per-request DEP warning, not the `console.error` from L208. But the pattern matches 2026-05-25 and 2026-05-28 exactly (200, no row, no log body) and the recent change set on main hasn't touched the social pipeline, so the upstream failure mode is the same (generator throw at `stage=generate`, likely Anthropic API hiccup or JSON-parse on truncated output).
