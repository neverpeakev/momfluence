## Diagnosis

Identical to PR #119 (open, unmerged for 2 days). Timeline from Vercel + Supabase logs for today:

- 14:00:42 `/api/social/fb-daily-generate` → 200
- 14:01:12 Supabase `markFbPublished` PATCH → 204
- 14:15:08 `/api/social/ig-mirror` → 200
- No subsequent DB writes; no render warm-up calls; no console output.

Direct SQL at 14:46 UTC confirms the row matches `listPendingIgMirror`'s filter (`fb_published_at IS NOT NULL AND ig_published_at IS NULL AND status='fb_published'`), so `pending` was not empty at 14:15.

The only path in `app/api/social/ig-mirror/route.ts` consistent with this trace is `fetchPageContext` throwing — but its catch returns `NextResponse.json({ ok: false, ... }, { /* status 200 */ })` with no `console.error`. Vercel's cron view treats the run as successful and the actual Meta-side error message is lost.

Likely underlying Meta failures (still unverifiable without merged logging):
- Page access token expired/revoked.
- `instagram_business_account` link to FB Page `1086292991223812` was broken or scope revoked.
- Sustained Graph 5xx with no retry.

## Fix

PR: **#TBD** — branch `claude/fix-content-cron-2026-06-13`, identical patch to PR #119.

- `console.error` on every failure branch (auth, env, page-context, per-row publish).
- Non-2xx status codes for non-recoverable failures (500 for env missing, page-context throw, per-row failures) so the Vercel cron health view flags them red.
- `console.log` summary on success / "nothing to mirror" / per-batch slug list so every run is traceable.

This is the same one-file change in PR #119. Filing a new PR per the routine spec; the actual goal is to get either PR merged so tomorrow's run is self-diagnosing.
