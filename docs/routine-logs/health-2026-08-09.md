## Root cause (code)
`ig-mirror` swallowed every failure and returned HTTP 200 with `{ok: false,
message}` — no `console.error`, no row marked `ig_failed`, no visible signal
anywhere. That's why the regression ran undetected for 10+ days after the
2026-07-29 audit.

Failure paths that were silent:
1. `META_MARKETING_API_TOKEN` / `META_FB_PAGE_ID` missing → 200
2. `fetchPageContext` throws (this case: IG unlinked) → 200, pending rows
   never marked failed → next run sees them pending, silently 200s again
3. Individual `publishToIg` failure → mark row `ig_failed` (worked) but
   endpoint still returned 200

Vercel runtime log for today shows only `14:15:08 GET /api/social/ig-mirror
200 [info/edge-middleware]` with no function-level entry, confirming zero
`console.error` output from any code path.

## Fix
PR: `claude/fix-content-cron-2026-08-09` — resilience patch for
`app/api/social/ig-mirror/route.ts`:
1. All three failure paths now `console.error` (surfaces in Vercel Runtime
   Errors dashboard) and return HTTP 500 instead of 200.
2. `fetchPageContext` failure now marks every currently-pending row
   `ig_failed` with the auth/page-context error message, so a future silent
   config regression can no longer stack up invisible backlog.

This code fix does **not** re-publish the 13 stuck rows — that's intentional
per the 2026-07-29 audit note ("prevent bulk-publishing stale content once
the IG link is restored"). Once the IG account is re-linked, the code fix
kicks in only for future posts.
