## Root cause of the invisibility
`app/api/social/ig-mirror/route.ts` had three early-return paths that all returned HTTP 200 via `NextResponse.json` with no `console.error`:
1. `META_MARKETING_API_TOKEN or META_FB_PAGE_ID not set`
2. `auth/page-context: …` (thrown by `fetchPageContext` — `/me/accounts` then `/{pageId}?fields=instagram_business_account`)
3. `nothing to mirror`

When (1) or (2) fired, `markFailed` was never called and the per-row loop never ran, so no row got an `error_message` and Vercel's runtime-error dashboard stayed empty. Today's 14:15:08 UTC GET completed in milliseconds with no body logs → almost certainly path (2): the `instagram_business_account` lookup throwing, or an env var unset since the May 27 deploy. The FB cron 15 min earlier still hits `/me/accounts` with the same `META_MARKETING_API_TOKEN` and succeeds, so the user token itself is fine — the break is IG-specific (page-token permission scope, or the IG link itself).

## Fix shipped
PR: https://github.com/neverpeakev/momfluence/pull/141 (branch `claude/fix-content-cron-2026-06-29`, draft)

`app/api/social/ig-mirror/route.ts` only:
1. New `markBacklogFailed` helper — when env or page-context fail, every row currently in the pending backlog is marked `ig_failed` with the root-cause message, so the DB shows what's actually wrong instead of accumulating silent zombies.
2. `console.error` on every failure path.
3. HTTP 500 when `failed > 0` (including pre-loop paths), so Vercel's runtime-error tracking fires. Vercel cron does not retry 5xx — it records it.

Deliberately does **not** touch the publish flow or the underlying Graph API issue. After this ships, the next 14:15 UTC run will write a real `error_message` onto each of the 28 pending rows pointing at the actual broken Graph call. That's the lead for the follow-up fix.
