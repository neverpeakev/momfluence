## What the cron actually did

Vercel runtime log for production deployment
`dpl_AspB65VqHmLMUtM5fP6HdrrmuMm3` (the funnel-rebuild deploy from
2026-05-31 18:58 UTC) shows exactly one log line for the cron:

```
14:00:42  GET /api/social/fb-daily-generate  200  error  (node:4) [DEP0169] Deprecat...
```

`DEP0169` is the Node `url.parse()` deprecation warning — a dep, not our
code. There is **no** `[fb-daily-generate] failed at stage=…` line, which
is what the route's catch block emits on any `try`-block failure
(`recent_context`, `generate`, `insert_pending`, `render`, `fb_token`,
`fb_publish`, `mark_published`). The optimizer cron ran fine at 06:00
and 12:00, so cron infra itself is healthy.

Status 200 + no catch-block log + no row in DB ⇒ the function exited via
the unguarded env-var early-return at `route.ts:140`:

```ts
if (!userToken || !pageId) {
  return NextResponse.json({
    ok: false,
    error: "META_MARKETING_API_TOKEN or META_FB_PAGE_ID not set",
    duration_ms: Date.now() - started,
  });
}
```

This is the *exact* silent-failure pattern PR #101 fixed in `ig-mirror`
(yesterday's diagnosis: a 200 with `ok:false`, no `console.error`, no DB
write, invisible to log scrapers). `fb-daily-generate` has the same hole
and PR #101 didn't cover it.

## Why now

Production cut over to the funnel-rebuild deployment at 2026-05-31
18:58 UTC — between yesterday's working 14:00 cron and today's broken
one. The funnel rebuild (PRs #99, #104) did not touch `lib/social/` or
`app/api/social/`, so the regression isn't in the social code itself.
The most likely cause is a missing `META_MARKETING_API_TOKEN` or
`META_FB_PAGE_ID` env var on the new production deployment — either
rotated/unset in Vercel project settings, or scoped to a target the new
deployment doesn't read from. Without env-var introspection over MCP I
can't confirm which.

## Fix in this PR

`claude/fix-content-cron-2026-06-01` makes the env-missing path loud:

1. `console.error` with the missing-var name so it shows up in Vercel
   runtime logs on the first failed cron (parallel to PR #101's
   `abortPending`).
2. Same fix structure to the matching path in `ig-mirror` is already in
   PR #101 — that PR is still open/unmerged at time of this writing.

This is a visibility fix only. It does **not** restore the missing env
vars — that requires a human to check Vercel project settings for
`momfluence-platform` (Production scope) and either re-set
`META_MARKETING_API_TOKEN` + `META_FB_PAGE_ID` or trigger a redeploy
that picks them up.
