## Code bug fixed in this PR
Regardless of the underlying Meta issue, the route had a silent-failure bug: all three pre-loop early-exit paths (`!userToken || !pageId`, `fetchPageContext` throws, missing scopes) returned HTTP 200 with `ok: false` and **wrote nothing to the DB**. Consequences:
- Pending rows stayed `status=fb_published` indefinitely.
- `error_message` was never populated, so the failure was invisible to anyone reading the DB.
- Every following day's cron picked the same rows back up and silently re-failed.
- No `console.error` either, so Vercel logs gave no signal beyond the 200.

PR: https://github.com/neverpeakev/momfluence/pull/101 (branch `claude/fix-content-cron-2026-05-31`)

Change in `app/api/social/ig-mirror/route.ts`: introduce `abortPending(reason)` helper that, on any pre-loop early exit, (a) `console.error`s the reason and (b) marks every row returned by `listPendingIgMirror` as `ig_failed` with that reason as `error_message`. Future infra-level failures will now surface in the DB and Vercel logs immediately, instead of accumulating silently.
