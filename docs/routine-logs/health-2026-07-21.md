## Diagnosis

FB cron works. IG mirror cron has silently failed every day since **2026-05-28**
(55 consecutive days). Last successful `ig_published` row: `gen-2026-05-27-p8u57`
at 2026-05-27 14:15:37 UTC. Since then, 46 rows sit at `fb_published` with no
`ig_failed` marker and no `error_message` — which is why nothing alerted.

Root cause of the silence (not the underlying IG failure — see below):
`app/api/social/ig-mirror/route.ts` had a global early-return path when
`fetchPageContext` threw (lines 178-192 pre-fix). It returned a JSON message
but did not call `markFailed()` on any of the pending rows. Same for the
`!userToken || !pageId` env-missing branch. Both branches also skipped the
per-row loop, so nothing wrote to Supabase at all — leaving rows stuck at
`fb_published` and looking indistinguishable from "still processing."

## Underlying IG failure — not yet identified

Vercel runtime logs aren't accessible from this environment. The route's
per-row error handler works (last two `ig_failed` rows on 2026-05-24 and
2026-05-26 both captured "IG status check → 400: Authorization Error … 
error_subcode: 33"), so the persistent failure has to be in one of the paths
that early-returned without persisting — most likely `fetchPageContext`:
either the Page Access Token no longer includes `instagram_business_account`,
the IG Business Account was unlinked from FB Page 1086292991223812, or the
system-user token lost the required scope.

The May 24/26 `error_subcode: 33` (nonexistent object) already hinted at IG
container/permission trouble; the shift from per-row errors to complete
silence starting 2026-05-28 lines up with a token/permission change that
promoted the failure from per-row to global.

## Fix in this PR

`app/api/social/ig-mirror/route.ts` — collapse both silent early-return
branches into a `failAllPending(reason)` helper that calls `markFailed()` on
every pending row before returning. Next cron run (or manual retrigger) will
surface the true Meta API error in `generated_posts.error_message`, and the
next daily routine will diagnose the root cause from there.

This is a diagnostic fix, not a functional fix. IG will still fail tomorrow —
but the failure will be visible instead of silent. Recommended follow-up
after that surfaces:
- Check `generated_posts.error_message` for today's slug after the fix
  deploys and the ig-mirror cron fires (or is retriggered manually).
- Based on the error, either refresh the FB Page → IG Business Account link
  in Meta Business Suite, or reissue the system-user token with the
  `instagram_basic` + `instagram_content_publish` + `pages_show_list` +
  `pages_read_engagement` scopes.
