## Root cause — same as PR #198 (open, unmerged, 6 days old)

Vercel runtime log for `/api/social/fb-daily-generate` on
`dpl_Gvbxxuy1j3CFJGHXUTDCRSWMouVS` (production, commit 8a63851):

```
14:01:31 GET /api/social/fb-daily-generate 200
[fb-daily-generate] failed at stage=generate: generateDailyPost failed
after 3 attempts. Last error: not valid JSON (first 200 chars: {
  "angle_tag": "school-book-fair-checkout-bookmark-rec",
  ...
  "display": "She named the magnetic bookmark
    at the school book fair.",
  ...
```

The model emitted a literal LF (0x0A) inside the `display` string
value. `JSON.parse` rejects control chars in string literals; all 3
retry attempts hit the same wall because the system prompt itself tells
the model that `display` "can use `\n` for line break"
(`lib/social/post-generator.ts:287,299`) and today it chose the raw
newline over the two-char escape sequence.

Because the failure happened at `stage=generate` (before
`insert_pending`), no row was written — the endpoint returned
`200 { ok: false }` and the DB has nothing to show for the day. IG
mirror ran 15 minutes later, found nothing pending, and no-op'd.

## This is a recurrence of 2026-08-18

PR **#198** — "Fix daily content cron: repair raw newlines in Claude
JSON output" — was opened by Claude on 2026-08-18 for **the identical
failure mode on the identical string field**. It adds
`escapeControlCharsInJsonStrings`, a small state-machine walk that
escapes raw LF/CR/TAB inside JSON string values before the second
`JSON.parse` attempt. It has been sitting in draft since 2026-08-18 and
has not been merged. In the interim we have now lost:

- 2026-08-18 (the original incident)
- 2026-08-24 (today)

Between those, the model happened to emit escaped `\n` and the days
went through.
