## Root cause

Two layered failures:

1. **External (the actual outage):** The IG mirror cannot publish. The May 23–26
   `ig_failed` errors point at a **Meta Graph permission issue on the IG side**
   — `error_subcode 33` ("Object does not exist, cannot be loaded due to
   missing permissions, or does not support this operation") at
   `GET /{creation_id}?fields=status_code`. The same
   `META_MARKETING_API_TOKEN` works fine for the FB Page (`fb-daily-generate`
   still publishes daily), so this is **not a fully-expired token** — it is
   either a) the IG-Business-Account link to FB Page `1086292991223812` was
   broken, or b) the token's `instagram_basic` / `instagram_content_publish`
   scopes were dropped/revoked. Linked IG account per project context is
   `17841442248205840`; needs manual verification in the FB Business Settings
   that this is still attached and that the system-user token still holds the
   IG scopes.

2. **Code (the reason this went silent for 27 days):** The early-return
   paths in `app/api/social/ig-mirror/route.ts` for "env not set" and
   "auth/page-context failed" returned `200 { ok: false, message: "…" }` and
   **never called `markFailed` on any pending row, never logged via
   `console.error`**. So the failures are invisible to:
   - the DB (no `error_message` written → routine health check sees only a
     bare `fb_published` row and cannot distinguish "IG cron hasn't fired
     yet" from "IG cron failed at the same step every day for a month")
   - Vercel runtime logs (no error-level log line, so log-level filters and
     dashboards stay silent)
   - Vercel cron retries (200 is "success" to the cron scheduler)

   The per-row `publishToIg` failures *do* call `markFailed` (which is why
   the May 23–26 rows recorded errors), but anything that throws before the
   per-row loop is reached gets swallowed.

## Vercel evidence

```
| 14:15:08 | GET | /api/social/ig-mirror | 200 |  |  |
```
No log lines at info/warn/error level for the request. No `console.error`
output. Consistent with the silent early-return path described above.

## Fix in this PR (code only)

`app/api/social/ig-mirror/route.ts`:
- Pull `listPendingIgMirror` *before* the env-var check so we know what rows
  are at risk.
- On env-var missing **or** `fetchPageContext` failure, call `markFailed` on
  every pending row with the diagnostic message and `console.error` the
  same.
- Return HTTP **500** (not 200) on those systemic failures so Vercel's cron
  alarms and any external uptime monitoring actually trigger.

This makes the underlying Meta-side outage **visible** on the next run — it
does not fix the outage itself.
