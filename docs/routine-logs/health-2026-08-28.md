## Diagnosis

The IG mirror cron fired on schedule and returned 200 but did not update the
row and did not set `error_message`. The `/api/social/ig-mirror` route has
four "returns 200 with a message field" branches that all lack any
`console.log`:

1. `META_MARKETING_API_TOKEN or META_FB_PAGE_ID not set`
2. `pending.length === 0` → "nothing to mirror"
3. `fetchPageContext` threw → returns 200 with `auth/page-context: …`
4. The per-row loop (this one would have flipped status to `ig_failed`,
   so we know we did not enter this branch).

Since (1) is ruled out (FB cron uses the same envs and succeeded) and (2)
is ruled out by a direct SQL check confirming the row matches
`listPendingIgMirror`'s filter, the almost-certain root cause is (3):
`fetchPageContext` threw — likely the `/{pageId}?fields=instagram_business_account`
call rejected (a scope/perms issue on the Meta token, since IG publish
requires `instagram_basic` + `instagram_content_publish`, which the FB post
flow does not).

Cannot confirm without observability: the endpoint returned the message
only in its JSON response body, which was discarded by the cron caller.

## Action taken

Opened PR [#209](https://github.com/neverpeakev/momfluence/pull/209) (branch `claude/fix-content-cron-2026-08-28`) that:
- Adds `console.error` / `console.log` at every early-exit branch in
  `/api/social/ig-mirror` so tomorrow's run is diagnosable from Vercel
  runtime logs.
- When `fetchPageContext` fails, marks every pending row as `ig_failed`
  with the underlying error in `error_message`, so the DB reflects
  reality instead of leaving rows silently stuck.
