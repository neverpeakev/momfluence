## Root cause

Two failures compounded:

1. **Meta-side issue** (why the outage started): FB and IG paths use the same
   `CRON_SECRET` and same `META_MARKETING_API_TOKEN` env vars, and FB is still
   working, so the delta is IG-specific — the extra
   `/{pageId}?fields=instagram_business_account` lookup in
   `ig-mirror/route.ts::fetchPageContext`, and the IG-only
   `instagram_content_publish` scope. 62-day timing matches a Meta long-lived
   token / IG-account-link expiration cycle. **Kevin has to fix this in the
   Meta UI** — either re-mint the token or re-link the IG Business Account
   (`17841442248205840`) to FB Page (`1086292991223812`).

2. **Code bug** (why it was silent for 62 days): when
   `ig-mirror/route.ts::fetchPageContext` throws, the route returns 200 with
   `{ message: "auth/page-context: ..." }` but **never touches Supabase**. Same
   for the `META_..._TOKEN` env-check early-return. The daily audit only reads
   `generated_posts`, so a whole-run auth failure looks identical to "cron
   didn't fire": no `error_message`, no `errored_at`, no `ig_failed` status.
   This is why the health check missed it for 60+ days.

## Fix

PR: (link in commit message once created) — branch `claude/fix-content-cron-2026-07-28`

Single-file change: `app/api/social/ig-mirror/route.ts`

- Fetch `pending` rows before preflight checks.
- On env-var missing OR `fetchPageContext` failure, call `markFailed(row, "ig", reason)`
  on every pending row so tomorrow's audit surfaces it immediately.
- Behavior for happy path and per-row failures is unchanged.

After this ships, if the Meta token is still broken tomorrow, the row for
2026-07-29 will land in Supabase as `status='ig_failed'` with a real
`error_message` — not another silent `fb_published`.
