## Root cause
Claude Opus 4.7 emitted a raw newline byte inside the `display` JSON string value. Payload captured from the log:

```
"display":"She named the shaker eggs
     during circle time.",
```

Raw newline + 5 spaces of pretty-print indentation inside the string — invalid per RFC 8259 §7 (control chars U+0000–U+001F must be escaped). `JSON.parse` failed, and all 3 retries hit the same failure mode because the prompt was actively teaching Claude to do it: the string `"can use \n for line break"` inside a TS template literal becomes a real newline byte, so Claude was being *shown* the raw newline and told to use it.

## Fix
PR: https://github.com/neverpeakev/momfluence/pull/149 (branch `claude/fix-content-cron-2026-07-06`)

`lib/social/post-generator.ts`:
1. Swap `\n` for `\\n` in both places in the prompt so Claude sees the two-character escape.
2. Add `escapeControlCharsInStrings()` — single-pass state machine that rewrites raw `\n` / `\r` / `\t` inside JSON string literals before `JSON.parse`. Structure outside strings is untouched.
3. Bump `MAX_TOKENS` 1500 → 3000 for headroom.
4. Detect `stop_reason === "max_tokens"` explicitly so a truncated response records a specific error on retry.

Verified against the exact raw payload from today's log — parses cleanly with the preprocessor.
