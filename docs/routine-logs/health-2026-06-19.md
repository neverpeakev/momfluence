Status: **broken — IG mirror silently failing for 9+ days**

Today's FB post published cleanly at 14:01:13 UTC. The IG mirror cron fired
at 14:15:08 UTC and returned HTTP 200, but the `generated_posts` row was

`error_message`. The routine's standard health check (which looks at
`ig_published` / `fb_failed` / `ig_failed`) has been blind to this because
the IG handler hits a silent-200 early-return path instead of marking
rows `ig_failed`.

## Root-cause diagnosis (Vercel logs)
- `/api/social/ig-mirror` GET → 200 at 14:15:08 (and every prior day at the
  same minute). No `error` / `warning` runtime-log entries from this path.
- No console output at all, despite the row being a clean match for
  `listPendingIgMirror`'s filter (`fb_published_at IS NOT NULL` AND
  `ig_published_at IS NULL` AND `status='fb_published'`).

The handler has three silent-200 exit paths before the publish loop:
1. `META_MARKETING_API_TOKEN` / `META_FB_PAGE_ID` missing → returns 200.
2. `pending.length === 0` → returns 200 "nothing to mirror".
3. `fetchPageContext` throws → caught and returns 200 with `ok:false`.

Path (1) is ruled out (the FB cron at 14:00 in the same deployment reads
the same env vars and posted successfully).
Path (2) is ruled out (today's row matches the filter; confirmed via direct
Supabase query).
Path (3) is the most likely cause. `fetchPageContext` does TWO Graph API
calls. The first (`/me/accounts`) is also used by the FB cron and demonstrably
works. The second (`/{pageId}?fields=instagram_business_account`) needs
`instagram_basic` + `pages_show_list` scopes on the user token, and the
linked IG Business Account must be reachable from that token.

Most plausible underlying issue: the long-lived `META_MARKETING_API_TOKEN`
in Vercel env lacks `instagram_basic` / `instagram_content_publish` scopes,
OR the Meta token was regenerated at some point without those scopes. The
silent-200 catch has hidden this for 9+ days.

Can't confirm definitively without manual cron re-trigger (need
`CRON_SECRET` from Vercel env) or inspecting the token's `/debug_token`
response (need access to a token with `app` scope). Both out of scope for
this routine — flagged for owner to verify.

## Fix
PR: see branch `claude/fix-content-cron-2026-06-19`.

1. `app/api/social/ig-mirror/route.ts` — surface every previously-silent
   failure:
   - env-missing → returns `500` (was implicit 200) + `console.error`.
   - `listPendingIgMirror` throw → wrapped in try/catch, returns `500` +
     `console.error` (previously would have crashed-but-200'd via Next.js
     default; now consistent with other paths).
   - `fetchPageContext` catch → returns `500` (was implicit 200) +
     `console.error` + marks every matched pending row `ig_failed` so the
     standard routine health check finds it instead of silent-looping.
2. `app/api/social/fb-daily-generate/route.ts` — same env-missing
   pattern: `console.error` + `500` (was implicit 200).

After this lands, the very next cron run (tomorrow 14:15 UTC) will either
succeed end-to-end or write a real `error_message` we can act on.
