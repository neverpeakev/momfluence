## Scope
- Last successful `ig_published` row: 2026-05-27 14:15:37 UTC.
- Stuck rows (fb_published, ig_published_at null, no error_message): **40**.
- All 40 rows are silent — nothing in `error_message`, nothing in Vercel `serverless` logs for `/api/social/ig-mirror`, and the endpoint has been returning 200 every day.
- No code touched `app/api/social/` or `lib/social/` since 2026-05-18 (last commit that could affect this: 28597e8, unrelated to IG). Regression is environmental (Meta API / token / IG-linkage) or was always latent and started firing after the ecosystem changed.

## Root cause hypothesis
`app/api/social/ig-mirror/route.ts` `fetchPageContext` throws, but the catch block returns 200 without ever calling `console.error` or writing anything to `generated_posts.error_message`. That single silent-exit path exactly matches the observed shape: 200 from the endpoint, no serverless log line, `status` stays `fb_published`, `error_message` stays null.

Two plausible triggers, both invisible until we log:
1. Meta Graph API v20.0 has aged past its 2-year window (released May 2024) — some field or response shape may have changed on v20.0's compatibility path.
2. The FB Page → IG account link now presents as `connected_instagram_account` (Creator/Personal-linked path) rather than `instagram_business_account` (Business-linked path). The current code asks only for the second field and throws if it's absent.

## Fix — PR to be linked below
Branch `claude/fix-content-cron-2026-09-07`. Two changes to `app/api/social/ig-mirror/route.ts`:

1. **Ask for both linkage fields** in the Page → IG lookup:
   `fields=instagram_business_account,connected_instagram_account`
   Accept whichever is populated. Covers Business, Creator, and Personal linkages without needing to know which one Meta will return.
2. **`console.error` on every silent-exit path** (env missing, page-context throw) plus a `console.log` of the pending-row count. Any future recurrence lands in Vercel runtime logs where this routine can see it on the next run.

Deliberately NOT done in this PR:
- Not marking the 40 stuck rows `ig_failed` — that status is documented as terminal in the file header ("will NOT be retried by future runs"), and if the fix works we want them retryable.
- Not bumping META_API_VERSION — separate risk, unclear whether v20.0 is actually the trigger.
