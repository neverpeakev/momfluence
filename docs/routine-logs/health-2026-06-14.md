## Bug (independent of root cause)
`app/api/social/ig-mirror/route.ts`:
1. When `fetchPageContext` throws, the catch block returns 200 with `ok: false` and `message: "auth/page-context: ..."` but does **not** call `markFailed` on the pending rows. Result: rows stay `fb_published` with empty `error_message`, indistinguishable from the healthy mid-state right after the FB cron lands. Every future IG cron will re-pick them and re-fail the same way.
2. None of the early-exit paths (nothing-to-mirror, env-missing, page-context fail) emit a `console.log`/`console.error`. Vercel runtime logs show the bare GET 200 with no body or message, so failures are invisible.

## Fix
PR: opening on branch `claude/fix-content-cron-2026-06-14`.
- `app/api/social/ig-mirror/route.ts` — in the `fetchPageContext` catch, call `markFailed(row.id, "ig", ...)` for every pending row with the wrapped error, so they exit `fb_published` limbo and `error_message` is set.
